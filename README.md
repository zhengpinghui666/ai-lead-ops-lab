## 启动

在项目目录先运行 `python manage.py doctor`，再运行 `./start.ps1`，打开 [本地工作台](http://127.0.0.1:8765/)。需 Python 3.10+、SQLite 3.35+，后端只用标准库；也可直接运行 `python server.py`。默认仅监听本机 `127.0.0.1:8765`。启动脚本支持 `-PythonPath`、`-Port`、`-DataDir` 与只读 `-Check`。迁移、备份、恢复和依赖配置见 [PORTABILITY.md](PORTABILITY.md)。

浏览器采集另需 Node.js（本机验证版本 24.19.0）、Playwright 1.62.1 与已安装的 Google Chrome。运行 `pnpm install --frozen-lockfile --ignore-scripts` 安装项目依赖，再运行 `python manage.py doctor --require-browser` 检查；不自动安装 Chrome。Node 从 PATH 或显式配置读取，Playwright 使用项目内依赖，不再自动寻找 Codex 缓存。依赖检查通过不代表已登录或外部通道可用。

## 自建采集器：当前使用方式

1. 切换到正式数据，打开“行业监控”，点击“新建采集”。
2. 选择关键词搜索（默认无畏契约陪玩）或提供完整 `/video/数字ID` 链接。暂不接受短链、任意网址或代理配置。
3. 第一批建议 1 个视频、每视频 10 条评论。本版上限 5 个视频、每视频 100 条。“同时读取的视频数”可设 1–4，默认 1；实际不超过视频数量，指定单视频任务为 1。2026-09-09 已分别完成 2 路和 4 路页面的小批量实测，不是平台安全频率或长期容量保证。
4. 点击“打开浏览器并采集”。专用 Chrome 使用 `data/browser-profile/`，与日常浏览器配置完全分离。登录会话属于敏感本机数据，不要上传或提交该目录。
5. 遇到登录、验证码或需要打开评论区时，任务暂停。按 **Alt + Tab** 切到本任务打开的 Chrome 抖音窗口，在该页面扫码登录或自行验证；不是在开发者后台或工作台登录。完成后回到行业监控，点击对应任务的“已处理，继续读取”。等待最多 10 分钟，整个会话最长 15 分钟；窗口超时关闭后可重新采集。未完成页面操作时不要反复点击继续。
   如果页面提示“使用原设备扫码”，需在原设备上的抖音完成账号验证；扫码登录与额外账号验证不是同一步。二维码失效时按页面提示刷新，不把停留在验证页视为登录成功。
6. 可随时停止。已入库数据保留；同一来源的重复评论不会重复创建。关闭或重启服务不会自动重新发起采集。任务卡显示当前读取页数、配置上限与本批并发峰值；旧任务未记录峰值时明确显示“未记录”。
7. “来源证据”显示观察时间、原视频链接和标准化记录摘要哈希；失败时还保留有限的可见页面诊断，不保存网络请求头、Cookie 或完整响应。
8. 任务在发现视频后保存视频级断点。结束的任务若仍有未完成视频，可点击“从断点继续”创建新会话：跳过已完成视频，中断视频重新加载并去重。这不是保存平台分页游标，也不保证补齐未加载的历史评论。

### 二级评论与回复证据

解析器支持评论列表响应中已附带的 `reply_comment` 一层回复，不主动请求回复接口，不递归展开更深数组。主评论与回复共用每视频评论上限；单个响应最多检查 1,000 条主评论/回复，截断不会作为完整读取证明。二级回复分页与“展开更多回复”的真实页面适配尚未验收。

- 有明确 `reply_to_reply_id` 时记录其所指评论，否则使用有效 `reply_id` 或嵌套主评论 ID；不把线程主评论冒充明确指向的直接上级。
- 只有同一来源、同一视频的上级评论才参与上下文。自指、循环、跨视频或已有上级 ID 冲突会拒绝该批写入；缺失上级允许保留，界面显示“未读到上级评论原文”。
- 线索详情、评论历史与人工核对均展示关联状态和已保存的上级原文。上级后来入库或修订时，受影响的规则结果重新待处理；不会覆盖人工分类。
- 上级上下文辅助识别游戏，并为“多少钱”等短询价提供服务语境；不把另一人的预算、区服、服务方向或联系意愿转给回复者。命中证据区标明取自评论、上级原文还是视频标题。
- 即使缺少用户 ID，也保存首次实际收到的评论昵称；仍不按昵称创建用户身份。旧数据不会凭空回填原始昵称，可在再次收到原记录时补齐。

除合成响应、临时数据库与隔离演示验证外，2026-09-09 真实任务 #10 已读到 2 条带上级 ID 的回复，两条上级均在同来源、同视频库中匹配；正式界面核对了其中一组上下文与同用户两条历史。仅证明响应内附带回复可用，**不代表二级评论独立分页或全量展开已经接通**。

### 有限采集计划

“新建计划”只保存配置，默认暂停。每计划最多 24 批，每批最多 5 视频 × 每视频 100 评论，批次间隔可设 300–86400 秒；这些是本产品资源限制，不是平台认可的安全频率。

- 启动前要求最近一批手动采集正常结束且实际读到评论；没有真实基线时不会自动发起访问。
- 运行中的计划按优先级排序，不同批次仍串行派发，共用单一专用浏览器。每批可配置 1–4 个视频页面并行读取；这不增加账号权限或平台额度。下一批间隔从上一批结束时计算；不同时区按实际时刻比较。
- 验证、访问限制或失败会暂停；服务重启也会暂停。暂停计划只阻止后续批次，当前会话使用采集任务上的“停止”。
- 计划按总批次计数，不会无限运行。可先保存“无畏契约陪玩 · 小批量验证”，待真实小批量验收后再决定是否启用。

2026-09-09 计划 #2 已实际执行两批指定视频读取：第一批新增 1 / 重复 9，第二批新增 0 / 重复 10；第二批在第一批结束 302 秒后启动，计划达到 2 批后完成，没有自动追加。多个计划之间的优先级竞争仍只有隔离测试证据。

### 本地处理与资源边界

关键词发现之后，视频目标交给有界页面池。每个读取页独立保存当前视频、评论计数、去重集合、分页状态和响应队列，避免多个页面串数据；完成一页后才接下一个视频。`collector_worker.cjs` 是稳定入口，`collector_runner.cjs` 负责会话、共享暂停与任务结算，`collector_reader.cjs` 负责单页读取，`collector_pool.cjs` 控制并发上限。

每个页面最多并行处理 2 个已接收响应、最多保留 8 个待处理响应；配置 4 个页面时分别最多 8 / 32。每页按响应到达顺序提交，页面间可以交错，由同一输出管道与后端事务串行持久化；不保证跨页面的响应到达全局顺序。滚动前先消化本页已接收响应，写入后端等待管道可写。超过缓冲上限显示“本机缓冲已满 · 已停止”，不无限堆积，也不假报完成。

任一页面发现验证或登录要求，其他页面暂停后续加载操作；人工继续后先复查该页面，确认提示解除再释放其他页。已经发出的请求可能继续完成，不宣称瞬间撤回全部请求。429、拒绝访问、停止或窗口关闭会停止派发后续视频，结算已启动工作后记录明确终态；主页面导航直接返回 429/403 时也立即通知所有读取页，不再先等待页面加载。不自动重试或切换账号规避限制。

单个响应体上限 8 MB；这不是整个 Chrome 的内存上限。真实双页面任务 #13 中，专用 Chrome 进程及其后代的工作集加总观测峰值为 2,428.0 MiB、私有提交量加总峰值 2,538.7 MiB；四页面任务 #14 分别为 3,495.9 MiB / 3,842.8 MiB。工作集可能重复计入共享页面，私有提交量也不等于物理内存；这只是约 25 秒和 19 秒单批采样，不是长期峰值或容量承诺。部分响应解析失败时显示部分读取，保留已入库记录和未完成断点；不将坏响应等同于零评论。

可用 `./scripts/measure-collector.ps1 -TaskId 14 -MaxSeconds 90` 只读采样本机任务与专用 Chrome 进程树。输出 JSON 行，不启动、重试或停止采集，不读取登录配置；指定任务结束、等待人工操作或到达采样时长后退出。`MaxSeconds` 只限制采样器，不改变采集任务上限。

工作台仅轮询本机 `/api/collector` 同步状态：可见页面有活动任务时约 2.5 秒、空闲时约 15 秒，页面隐藏时暂停；这不是对抖音的轮询，不会自动启动采集。编辑表单时延后更新界面，避免刷新丢失输入。

本版只读取普通页面加载产生的搜索结果和评论，不直接重放私有接口请求、不解算签名、不绕过验证。读取范围不局限于自有账号，但只覆盖实际可访问且已加载的内容。页面结构可能变化；解析不支持时不能声称已经获得全量数据。只发现视频不等于已经采集到评论。

### 纯 HTTP 可行性检查（接入之前的历史诊断）

以下记录发生于 HTTP 通道接通之前。最新代码与实测见 [COLLECTION_HTTP.md](COLLECTION_HTTP.md)。浏览器后台的 `headless` 开关只是隐藏窗口，不能作为纯 HTTP 成功证据。

`node scripts/probe-public-http.cjs https://www.douyin.com/video/7664994032866659594` 是单视频、单次普通 HTTP 诊断，不是生产采集器。它不启动浏览器、不读取登录配置或 Cookie、不跟随跳转、不执行返回脚本、不重试；15 秒超时，最多读取 1 MiB 响应。不支持任意主机、自定义接口参数或凭据。只输出状态、结构提示、字节数与摘要哈希，不写正式数据。可显式加 `--comments` 检查固定评论入口（该视频、游标 0、请求 10 条），不会先访问网页，也不会自动追下一页。两个模式每次都只发一个请求。

2026-09-09 21:26:35 的首次真实诊断：HTTP 200、72,914 字节 HTML，包含 2 个脚本，无可见正文，未发现检查的内嵌数据/评论标记，未解析出真实评论。结果为 `html_without_verified_comments`，评论数量为未知而非零。这只证明本次匿名页面直连没有完成评论读取，不证明所有 HTTP 路径不可行；仍缺少可持续直接读取评论的数据通道证据。诊断结果不能包装为采集成功或获客结果。

21:33:09 对固定评论入口做一次普通匿名请求，结果 HTTP 200、`application/json`、响应体 0 字节，状态 `empty_response`，没有评论或分页游标。不能将其当作有效的零评论 JSON，也不能仅凭空响应推断缺少哪项参数、登录或签名。该次没有使用身份、签名、请求头伪装或代理。可识别但存在跳过/截断的 JSON 返回 `partial_comment_json`，不作为完整诊断成功。

用户已允许仅在首次登录/人工验证时使用浏览器，正常采集不用浏览器内核。`node scripts/probe-session-http.cjs https://www.douyin.com/video/7664994032866659594` 是另一项显式授权会话诊断：只打开本项目的专用 profile，按评论网址作用域读取该会话 Cookie，等待浏览器关闭后，在同一进程内发出一次 HTTP 评论请求。不导出 Cookie 文件，不读取日常浏览器配置，不把令牌放进命令参数、环境变量或日志；登录浏览器自身可能产生正常流量，结果中的 `requests` 只计 HTTP 检测阶段。没有找到会话、打开/关闭失败时，不请求评论，也不会自动退回浏览器采集。认证库使用项目依赖或显式 `CLUBOPS_PLAYWRIGHT`，专用会话位置跟随 `CLUBOPS_DATA_DIR`；不自动安装。

21:57:49 的实际会话诊断：附带 53 项按 URL 作用域取得的 Cookie，关闭认证浏览器后请求；109 ms 返回 HTTP 200、`application/json`、0 字节，仍未取得评论。Cookie 存在不证明当前登录有效或具备接口权限。请求后专用 Chrome 根进程为 0；正式库仍是 65 条评论。此结果证明认证会话读取与 HTTP 阶段可以分离，**不证明真实 HTTP 数据通道已经可用**。没有生成签名、伪装请求头或增加并发重试。

22:09:39 根据旧版作者接口资料补充固定普通参数 `aid=6383`，保持视频、游标、条数和 HTTP 标识不变，再做一次授权会话检查：119 ms 返回同样的 HTTP 200 / 0 字节空体，未入库。当前评论诊断包含该参数，但不代表请求参数完整；参考资料与结果见 `VALIDATION.md`。这个单次诊断每次运行都会打开/关闭专用会话，**不是**最终“仅登录时打开浏览器、正常采集长期复用 HTTP 会话”的运行服务；后者尚未接通，不能拿诊断脚本代替。

## 规则初筛与人工核对

当前版本为 `rules-v3`，没有通过真实语义模型推理验收，也没有经过真实独立标注集验证的准确率或概率分数。历史记录保留当时的版本，升级不自动清空或重算，详见 `RULES.md`。

- “找个搭子”“找个人带我”没有明确付费或服务询价时保留待判断；明确免费组队才归为免费社交。
- 分离购买服务、接单求职与招募信号。接单和购买并存、转述举例、多游戏冲突等保留待判断，不自动当客户。
- 服务需求和询价仅为潜在需求，不等于已经付费。询价需要服务语境；原文明指皮肤或设备等物品时不当作陪玩询价。
- 常见否定词不作为正向命中；保留明确人数限定、预算范围、时间原文。同字段有多个不同值时不任意选一个，并显示待核对项。
- 详情、历史和核对弹窗可展开“查看初筛依据”：显示规则版本、原文片段、来源层级、否定标记与冲突提示。每条最多展示 40 个命中片段，并非全文语义分析。
- 核对表单默认仅修改分类、保留现有字段；可选择“同时核对并保存以下字段”，修正游戏、服务、区服、段位、时间、预算和人数。每字段最多 120 字，留空表示人工确认该字段未知，不回退成规则值。纠正或撤销字段必须填写依据。
- 人工字段单独保存，原文、原始 ID、时间和先前规则片段不改写；详情明确显示人工字段，筛选、候选匹配和模板使用有效值。未经人工纠正的字段仍是规则信息。分类确认不等于确认全部抽取字段，也不授予联系权限。
- 可撤销字段纠正并恢复先前规则值，人工分类仍保留。保存时检查核对版本；原文或判断已变化的旧表单会拒绝覆盖，需刷新后重新核对。
- 每次核对保存原文、规则快照、字段前后值和判断依据；界面显示最近 10 次，数据库保留更早历史。评论原文修订时清空当前人工字段并重新待处理，但旧核对记录保留并注明原文已修订。旧版人工判断不会伪造回填审计记录；升级规则不覆盖人工分类、负责人或跟进记录。

规则仍可能误读复杂否定、俚语、跨句指代、多个服务和语境；时间不自动解释成日历预约，预算不自动推断计价单位，人员匹配不作价格或排期承诺。需要人工结合原页面判断。

## 历史数据兼容接口（不作为产品操作流程）

界面已经移除 CSV/JSON 导入、导出按钮、文件选择与粘贴弹窗。正常流程由采集器直接入库并对本批评论自动初筛，不需要人工搬运 UID 文件。原有本地接收/归档接口保留兼容用途，不删除历史来源、评论或任务，也不表示真实私信已经接通。以下是兼容接口的数据约定。

接受 UTF-8 CSV 或 JSON 数组 / `{"records": [...]}`。每次最多 5,000 条、请求体最多 2 MB。

必填字段：`comment_id`、`video_id`、`text`。可选：`user_id`（或 `uid` / `open_id`）、`nickname`、`video_title`、`video_url`、`published_at`、`parent_comment_id`。

- 只有提供用户 ID 才建立用户线索；不按昵称合并，不把用户 ID 当评论 ID。
- 评论以“来源 + 评论 ID”去重；原文变更会保留修订历史。同用户不同评论全部保留。评论 ID 对应的视频/用户冲突会拒绝整批导入。
- 时间接受 ISO 或 Unix 秒/毫秒；无时区 ISO 默认北京时间。未提供发布时间就显示未知，不拿入库时间冒充发布时间。
- 导入不会授予联系权限；来源链接只是可追溯字段，不代表应用已验证网页或数据真实性。
- 使用“运行初筛”处理待处理记录，单批最多 1,000 条。设置中的并发数只控制本地计算，不控制平台请求。
- JSON 导出包含评论证据与跟进记录，属于归档格式，不是全数据库备份或直接重导入模板。数据库可用 `python manage.py backup --to <新备份目录>` 在线生成一致快照；登录目录和本机认证配置不包含在该备份中，详见 `PORTABILITY.md`。
